# تشغيل خط الأساس وتعديل مهمة يدويًا

افتح `notebooks/current_baseline.ipynb`. أقسامه الثمانية: 1) المشروع والبيئة، 2) البيانات والتحقق، 3) المعالجة والإعدادات المشتركة، 4) FORECAST، 5) HIDDEN، 6) HIDDEN-FUTURE، 7) MISSING، 8) الجمع والتحقق والحفظ. كل مهمة تعرض أهدافها ومقتطف مدخلات مسموحة ونتائج صغيرة، وتفصل الإعدادات عن التدريب/التحميل وعن التنبؤ.

من جذر المستودع في PowerShell، جهّز Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

ضع ملفات المسابقة الرسمية الأربعة في `data/raw/` واختر نواة `.venv/Scripts/python.exe`. شغّل **Restart Kernel ثم Run All**؛ أو:

```powershell
.\.venv\Scripts\python.exe scripts/run_current_baseline_notebook.py
```

الخرج الافتراضي: `outputs/current_baseline_manual/submission_current_baseline.csv`. بجانبه `verification.json` و`task_config.json`، ونسخة منفذة منفصلة من الدفتر عند استخدام المشغّل. ملف الدفتر الأصلي لا تُحفظ فيه نتائج التنفيذ تلقائيًا. لا يحتاج التشغيل تقديمًا قديمًا أو ذاكرة محلية أو مجلد Downloads. الأصول المجمدة في `models/current_baseline/` مطلوبة ومضمنة بالمستودع.

## الملفات والدوال التي تعدّلها

| المهمة | الدوال المشتركة في `src/baseline_tasks.py` | التنفيذ الأساسي |
|---|---|---|
| FORECAST | `condition_forecast`, `forecast_value`, `im_forecast_value` | `t05_forecast/gp.py:predict_recording/predict`؛ `t05_forecast/pipeline.py:make_template`؛ `src/im_forecast_fallback_trial.py:predict/context` |
| HIDDEN | `fit_hidden`, `hidden_value` | `src/v2_hidden.py:fit/predict/_design` |
| HIDDEN-FUTURE | `fit_hidden_future`, `hidden_future_value` | `src/v2_experiments.py:direct_feature/fit_direct/predict_hf`؛ `src/prayer_experiments.py:fit_direct_variant/predict_direct_variant` |
| MISSING | `fit_missing`, `missing_value` | `src/v2_missing.py:fit_calibration/predict/deviations/gap_context` |

دوال `predict_*` في `baseline_tasks.py` تحول صفوف الإنتاج إلى استدعاءات للدوال المشتركة. `baseline_workflow.py` يحمّل الملفات ويجمع IDs ويحفظ تنسيق الأرقام القديم؛ ليس المكان المناسب لإضافة ميزة أو خوارزمية. `current_baseline.run` يستدعي هذا المسار الجديد، بينما `run_legacy` سلسلة تاريخية للاطلاع فقط. لا يستخدمها الدفتر الجديد أو المقيم الجديد.

يحفظ الدفتر إعداداته الفعلية في `task_config.json`. خلايا التعديل لكل مهمة هي المصدر لهذا الملف؛ تغيير JSON يدويًا ثم Run All يعيد كتابة إعدادات الخلايا. عند التقييم مرر **الملف الصادر عن تشغيلك** حتى لا تختبر الإعدادات الافتراضية بالخطأ.

`pipeline.table` مشترك بين المهام ويحافظ على NaN وحدود التسجيلات. `v2_hidden.fit` يساهم أيضًا في مرجع HIDDEN-FUTURE، و`v2_missing.interp_at` يؤثر في قراءة مانحي HIDDEN. افحص المهام المتأثرة عند تعديل دالة مشتركة.

## ما يحتاج إعادة تدريب؟

- FORECAST: أوزان المزج وحداثة I–M فعالة عند التنبؤ. ملفات covariance الاثنا عشر **محملة فقط**؛ لا توجد إعدادات تدريب ظاهرة توهم بتغيير نموذج محمل. تعديل `rank/ells/steps` أو بنية الملاءمة يحتاج أصولًا وذاكرة تقييم جديدتين وبيان بصمات مستقلًا، ولا ينفذه هذا الدفتر. `preflight` يرفض تغيير إعدادات/أصول الأساس المجمدة. تغيير خوارزمية الاستدلال المشتركة يصل للدفتر والتقييم، لكن قيم المعلمات المحملة تظل ثابتة.
- HIDDEN: تغيير `alpha` يعيد ملاءمة Ridge في خلية التدريب. أوزان B/G/D إعدادات مزج عند التنبؤ. لا توجد أصول Ridge قديمة يُعاد تحميلها خفية.
- HIDDEN-FUTURE: `model_params` تمر فعليًا إلى نموذجي HGB، لذلك أعد خلية التدريب بعد تعديلها. تعطيل ثم إعادة تفعيل نموذج السبت يحتاج تدريب النسخة مرة أخرى. وزن المزج عند التنبؤ فقط.
- MISSING: الأوزان والحد الأدنى لطول الفجوة عند التنبؤ. تعديل معايرة الأزواج في `fit_calibration` يستلزم إعادة خلية معايرتها. النماذج الصغيرة والمعايرة تعاد من train عند Run All، ولا يوجد تعديل T05 نتيجة ذلك.

أعد النواة بعد تعديل ملفات Python؛ تشغيل خلية import مرة أخرى وحده قد يبقي نسخة قديمة. إذا كتبت خوارزمية جديدة لـmissing، أعد أيضًا علامة `used` الصحيحة مع القيمة، فالقيمة المرجعية غير المتغيرة لها مسار تنسيق يحافظ على نصها الأصلي.

## التقييم المحلي من المصدر نفسه

مثال تعديل MISSING؛ بدّل `--task` بأحد `forecast`, `hidden`, `hidden-future`, `missing`:

```powershell
.\.venv\Scripts\python.exe src/evaluate_baseline_task.py --task missing --config outputs/current_baseline_manual/task_config.json --output-dir outputs/evaluation/missing_v1
```

الأداة ترفض مجلدًا سبق أن حفظت فيه توقعات؛ اختر اسمًا جديدًا. تقاريرها `by_date.csv` و`by_date_camera.csv` و`scored.csv` و`verification.json`. ملف `predictions.csv` يُحفظ قبل ربط الإجابات للتقييم. المعادلة المطبعة نفسها: MAE الطريقة / MAE مرجع الطية على الأهداف نفسها؛ متوسط المهمة المعتاد يعطي التاريخين وزنًا متساويًا.

المقيم يستبعد تاريخ التقييم بالكامل، ويستدعي دوال المهمة نفسها. HIDDEN يختبر حجب الكاميرات معًا، وHIDDEN-FUTURE يختبر عدم تأثر التنبؤ بالمشاهدات بعد now. الاختبار الثابت يتضمن 2036 forecast و843 hidden و482 hidden-future و358 missing. إن توفرت ملفات `outputs/local_score/` يتحقق من بصماتها ويقرأها فقط؛ وإن غابت في clone جديد يعيد بناء الحالات والأقنعة نفسها من الملفات الرسمية في مجلد التقييم الجديد دون الحاجة إلى نتائج تجارب قديمة.

**قيد FORECAST:** يلزم وجود 12 أصل ملاءمة تاريخية مستقلة في `outputs/local_score/t05_fit_cache/`. لا تستبدلها بأصول الإنتاج؛ فهي تشمل تاريخ التقييم. المقيم الجديد لا يدرب T05 ولا ينشئ هذه الملفات تلقائيًا. الاختبار التاريخي يستخدم عينة 96 خلية للتدريب وتغطية قالب محدودة، وليس إعادة إنتاج لدقة الإنتاج أو تحققًا حديثًا مستقلًا. لتغيير بنية الملاءمة يلزم بروتوكول منفصل لإعادة بناء الأصول وذاكرة تقييم ملائمة؛ هذا خارج أمر التقييم الآمن الحالي. `scripts/run_local_score.ps1` التاريخي قد يعيد ملاءمة T05 عند غياب ذاكرته ويكتب في مجلداته القديمة؛ لا تستخدمه بديلًا تلقائيًا.

كذلك يحتفظ الاختبار التاريخي بمرجع آخر قراءة حتى 30 دقيقة عند غياب توقع النموذج؛ الإنتاج يستخدم حد خمس دقائق. هذا اختلاف معروف في بروتوكول المرجع، وليس مسار خوارزمية منفصلًا خفيًا. دالة الاستدلال ووزن المزج مشتركان، وتقرير التقييم يوضح المقارنة مع التوقعات التاريخية المحفوظة.

**تقييم I–M المنفصل:** لا توجد إجابات I–M في الاختبار التاريخي أعلاه. يوجد مسار بروكسي يستدعي `im_forecast_value` نفسه وبالإعدادات نفسها:

```powershell
.\.venv\Scripts\python.exe src/evaluate_baseline_task.py --task forecast-im --config outputs/current_baseline_manual/task_config.json --output-dir outputs/evaluation/forecast_im_v1
```

يخفي قراءة محررة لاحقة بالنسبة لـnow ويستخدم التاريخ السابق فقط، دون تدريب على قراءات test. هذه حالات متداخلة على التاريخين اللذين سبق فحصهما؛ لا تمثل إجابات الأهداف الحقيقية أو إثبات نقل إلى كاميرات جديدة. لا تفترض نقل أي نموذج A–H إلى I–M لـmissing.

`local_score.fit_fold/predict_case` التاريخيان يستخدمان الآن الدوال المشتركة نفسها بالإعدادات الافتراضية. المقيم الجديد هو المسار الذي يقرأ إعدادات خلايا الدفتر من JSON. مراجع الإنتاج مأخوذة من العينة الرسمية؛ مراجع التقييم يعاد بناؤها داخل الطية، لذلك لا تساوي درجة Kaggle.

## الفرع والمرشح والـcommit

1. `git switch -c task/missing-update`
2. عدّل مهمة واحدة في المصدر المشترك أو خلية الإعدادات. في القسم 1 اختر مجلد OUTPUT مستقلًا واسمًا مثل `submission_missing_manual_v1.csv` واضبط `VERIFY_ACCEPTED=False` للتعديل المقصود. لا تغير البصمة المقبولة.
3. Restart Kernel ثم Run All. وضع إعادة الإنتاج الافتراضي يبقى `VERIFY_ACCEPTED=True` ويتوقف عند أي فرق.
4. شغّل تقييم المهمة مع مسار `task_config.json` الجديد. راجع التاريخين والكاميرات والفجوات/النوافذ، لا الصفوف المتجاورة بوصفها أدلة مستقلة.
5. راجع `git diff` ثم أضف الدفتر والمصادر والدليل ذي الصلة فقط، مثل:

```powershell
git add notebooks/current_baseline.ipynb src/baseline_tasks.py
git commit -m "Describe the task change and validation"
```

البيانات والتقديمات والنواتج مستبعدة من Git. سجل اسم المرشح ونتائج التقييم في وصف التغيير. لا commit أو push أو رفع آلي. المرشح غير الخطي D-only معطل افتراضيًا؛ تشغيله يستدعي الطريقة المحفوظة سابقًا مع fallback، ويتطلب اسم إخراج مستقلًا، ولا يثبت فائدة الاختبار المخفي.
